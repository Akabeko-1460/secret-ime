# SecretIME — Private alpha

**プライベート窓を開いたとき、Google日本語入力のシークレット設定をONにする操作を試みるWindows向けの試作ツールである。**
Chromium系ブラウザの拡張と、小さなWindowsホストで動作する。
入力・URL・閲覧履歴を取得せず、インターネットへデータを送信しない。

この版は設定操作の実装を含むPrivate alphaである。
製品版Google日本語入力での永続学習停止と、4ブラウザの実機動作はまだ実証していない。
このPCでは公式ツールの署名とUIの設定読取を確認した。ON/OFF操作と学習停止の実証は未完了である。
設定を読めない環境では`unavailable`とし、保護成功とは表示しない。

## 使い始める

**[Releases](https://github.com/Akabeko-1460/secret-ime/releases)から最新の`SecretIME-…-Setup.exe`を取得し、ダブルクリックする。**
追加ソフト・Node.js・PowerShell操作・再ビルド・管理者権限は不要である。
確認欄を選び「導入する」を押すと、現在のWindowsユーザーへの配置と登録が完了する。
続けて画面の案内に沿い、ブラウザへ拡張を読み込んでシークレット実行を許可する。

導入先は`%LOCALAPPDATA%\Programs\SecretIME`で固定する。
既存の登録・ファイルは導入先の`backups/`へ保存する。IME設定は導入中には変更しない。
拡張の連動は初期無効のままであり、利用者がポップアップから有効にする。
詳しい手順と更新・解除方法は[導入ガイド](docs/install.md)を参照する。

Setupは現在コード署名がなく、Windowsの保護機能で警告・ブロックされる場合がある。
保護設定を無効にせず、入手元とSHA256を確認し、不明なら実行を見送る。

## 初期版の動作

1. 利用者が拡張の連動設定を有効にする。初期状態は無効である。
2. private窓がある間、公式設定画面からシークレット設定を読み、OFFを確認した場合だけONにする。
3. 複数のブラウザ・プロファイルの要求を、同じユーザーのブローカーでまとめる。
4. 最後のprivate窓を閉じても、ONを保持する。通常入力へ戻すときは拡張の「復元」を押す。
5. 通信ホスト・ブローカー・UIワーカーは、最後の接続が終わると終了する。

復元中は、どのブラウザでも新しいprivate窓を開かない。
復元直前の窓確認と、新規ウィンドウの生成をOS全体で原子的に同期する機能はない。

開始前からONだった設定はOFFに戻さない。
手動変更や状態不明を観測した場合は、推測で復元しない。
異常終了で所有権が不明なら、Google日本語入力のプロパティから手動で確認する。
正常終了した変更は復旧マーカーを引き継ぎ、後から明示復元できる。

**自動OFFと継続監視は、この版では実装しない。**
公開APIで途中の手動変更を確実に識別できないため、自動復元を避けた。
表示は最後の確認結果であり、その後の手動変更やIME切替を監視した結果ではない。
private窓を開いてから設定が有効になるまでの入力を保護する保証もない。
機密入力の前に最新状態を確認し、実効性が必要な環境では手動設定を併用する。

## 要件と対象

- Windows 11 x64。OS付属の.NET Framework 4.xと既存のC#コンパイラを使う。
- 製品版Google日本語入力の公式設定画面が、必要なUI Automationパターンを公開していること。
- Chrome、Edge、Brave、Vivaldiを想定した共通MV3拡張。実機対応の認定は未完了である。
- 4ブラウザで同じインストール先・拡張IDを使い、同じWindows対話セッションで利用する。

Microsoft IME・ATOKの設定は操作しない。
使用中のIMEを自動判別して切り替える機能はなく、操作対象はGoogle日本語入力の設定だけである。
その設定は通常窓や他のアプリにも作用する。

## 開発者向け：ビルドと確認

PowerShellでリポジトリのルートから実行する。
依存パッケージのダウンロードや管理者権限は不要である。
`-Test`には導入済みNode.jsが必要となる。

```powershell
.\scripts\build.ps1 -Test
node --test tests/transport.test.mjs
.\scripts\build-setup.ps1
.\build\SecretIME.SetupTests.exe .\dist\SecretIME-0.1.0-alpha.2-Setup.exe
```

`--diagnose`は設定を変更しないが、読取のため公式プロパティ画面を一時的に開くことがある。
署名を確認できないツールや、既に開いている設定画面は操作しない。
チェックボックスの識別子・状態取得・設定後の再読取のいずれかが失敗したら、不明を返す。
UIプロバイダーが応答しない場合は自分のUIワーカーだけを終了し、IMEやブラウザを強制終了しない。

## ソース・ZIPから手動で登録する場合

製品ZIPにはビルド済みホストを含む。ソースから利用する開発者だけ、先にビルドする。
既に使っている版を更新する場合は、全ブラウザの連動を無効にし、private窓を閉じ、復元の要否を確認する。
このフォルダーは登録後に移動しない。

```powershell
# 登録予定を表示する。書込みはしない。
.\scripts\install.ps1 -EnableAutomation -WhatIf

# 現在のWindowsユーザーにホストを登録し、公式UIの操作を許可する。
.\scripts\install.ps1 -EnableAutomation
```

登録先はHKCUのNativeMessagingHostsだけで、HKLM・自動起動・サービスは使わない。
既存登録・生成設定を変更する前に、`backups/`へ保存する。
他のインストール先を指す登録は上書きしない。
`-EnableAutomation`なしでは連動制御を無効にする設定を生成する。
利用者が明示的に実行する`--diagnose`は、この設定と別にUI読取を試みる。

各ブラウザの拡張管理画面でデベロッパーモードを有効にし、`extension/`を「パッケージ化されていない拡張」として読み込む。
拡張詳細でprivate／シークレット／InPrivateでの実行を許可し、拡張のpopupから連動を有効にする。
拡張IDは`djbbbndacfniipaiopkjbeipamnjaneo`である。
表示されるIDが異なる場合は、そのIDを確認して`install.ps1 -ExtensionId <ID> -EnableAutomation`で登録を合わせる。

4ブラウザの登録キーとChromeフォールバックの実機確認は残っている。
ホストに接続できないときは、警告を表示して自動再接続を繰り返さない。
同じprivateセッション中の再試行は利用者の明示操作で行う。
すべてのprivate窓を閉じた後、新しいprivateセッションでは再試行できる。

## 解除する

全ブラウザの連動を無効にし、private窓を閉じる。
Google日本語入力のプロパティで元の設定へ戻ったことを確認する。

```powershell
.\scripts\uninstall.ps1 -WhatIf
.\scripts\uninstall.ps1
```

解除スクリプトは確認後に自分のホスト登録値だけを外す。
IME設定、ファイル、復旧マーカーを削除しない。
