# Private alphaの検証記録

日付：2026-10-31。Windows 11 Home 10.0.26200、既存の.NET Framework x64コンパイラとNode.js v24.11.1を使用した。
追加パッケージ・ブラウザ・ランタイムのダウンロードはしていない。

## Setup対応版の追加検証（0.1.0-alpha.2）

一般利用者向けに、配布ファイルを内蔵した日本語の単体Setup.exeを追加した。
セットアップを起動せず、レジストリを疑似実装へ差し替え、ファイル操作を`build/test-runs/`内へ限定して検証した。

- 拡張：30件成功。既存ONを維持した際の説明と警告を保持する回帰試験を含む。
- Core・通信形式：20件成功。
- IME制御を無効にしたNativeプロセス結合：3件成功。
- Setup：12件成功。4登録先、異なる登録の拒否、既存フォルダーの保護、配布パス逸脱・重複の拒否、更新バックアップ、復旧情報保持、導入・解除失敗時のロールバック、実配布EXEの内蔵ZIP検査を含む。

計65件の自動テストが成功した。SetupのGUI実行、実HKCUへの登録、実ブラウザへの導入、IMEのON/OFF・学習停止試験は行っていない。
UI起動中の例外でも自分が開いた画面へ閉じる要求を出すよう修正し、UIワーカーの失敗保持を1操作内に限定した。
後者は操作終了後の明示的な再要求を可能にする修正であり、自動監視・自動再試行を追加したものではない。
実UI例外の再現はしていないため、静的確認と自動テストの範囲を超える動作保証はしない。

Setupはx64 .NET Frameworkのビルド済み実行ファイルで、追加ダウンロードは行わない。
コード署名・ストア配布は未対応。Windowsの保護機能や組織ポリシーによって実行・拡張読込が制限される場合がある。

## 実行した検証

- C#ホストのビルド成功。実行ファイルは35,328バイト。最終配布物はCIと配布ZIPで生成する。
- 状態管理・厳密なフレーム処理：20件成功。複数lease、初期ON、手動OFF、不明状態、異常終了、正常所有権引継ぎ、明示復元、部分読取、重複JSON等を含む。
- 拡張の機能・回帰試験：29件成功。復元前の窓確認、異常終了時の永続マーカー、45秒の待機上限、確認時点を示す表示を含む。
- 実Nativeホストの結合試験：3件成功。別プロセス間でleaseを共有し、片方の終了後も他方の要求を保持した。未許可originと不正schemaを拒否した。
- 最終接続終了後、専用ホスト・ブローカーが残らないことを確認した。制御を無効にした環境での測定であり、実IME操作時の性能値ではない。
- Playwrightの既存Chromiumで実際の拡張を読み込み、固定ID・初期無効・popup描画・横幅・ページエラー不在を確認した。
- install/uninstallの`-WhatIf`、拡張ID算出、未知登録拒否、PowerShell構文を確認した。実レジストリ更新は実行していない。

Native結合試験は、隔離したビルド用フォルダーに`automationEnabled=false`の設定を作って実行した。
Google日本語入力のUIや学習履歴には触れていない。
実際のprivateブラウザから登録済みホストを呼び出したE2Eとは区別する。

popup画像はローカルの`build/test-runs/browser-c973c96043ee491a9aa4b7528efe52de/popup.png`に保存し、目視でも確認した。
ブラウザ試験は新規プロファイルを使い、既存の個人ブラウザプロファイルを使っていない。

## 製品版UIと学習の実測は未完了である

製品版Google日本語入力3.34.6260.0の公式ツールについて、Google署名の検証は成功した。
最初の読取診断は`modeEnabled=null`だった。
公式プロパティ画面のアクセシビリティ情報からQt完全修飾IDとTogglePatternを確認し、対象の識別条件を修正した。
その後の`SecretIME.Host.exe --diagnose`は`toolTrusted=true`、`modeEnabled=false`、`effectiveness=unverified`を返し、設定の読取に成功した。
設定の変更・確定や語句の入力はせず、ON/OFF制御・学習停止の成功を確認した結果ではない。
既存の設定プロセスがある場合も、画面を横取りせず利用不可とする。

Chrome・Edge・Brave・VivaldiとGoogle日本語入力・Microsoft IMEの学習永続性試験は、0/8組合せである。
Microsoft IMEの既存保護には介入する実装を入れていない。
CPU、実IME制御中のメモリ、設定完了までの遅延、再起動後の学習停止は未測定である。
設定後の継続監視・自動OFF・入力前保護も実装していない。

## 独立レビューと修正

実装者とは別のエージェントが、Core、拡張、ホスト、スクリプト、文書をレビューした。

| 指摘 | 対応 |
|---|---|
| Coreの実行中所有権だけでは正常停止後の明示復元ができない | clean-ownedマーカーと継承を追加。dirtyな異常終了とは分離し、20件のCore試験で確認 |
| 最初の接続終了で他の要求も失う | ブローカーの寿命を全接続数で管理。実プロセス結合試験で確認 |
| journal例外で切断時のcleanupを飛ばす | finallyで接続数と終了処理を保証 |
| pipe上限にlistenerの枠がない | OSの最大instanceとアプリの64接続制限を分離 |
| UI providerが停止して全体が固まる | 別の自前ワーカーに隔離し、応答期限を設定。操作後にワーカーを終了し待機中のメモリを減らす |
| 待受先のなりすまし | 現在ユーザーACLに加え、両方向で相手の実行ファイルと対話sessionを確認 |
| 継続監視しないのにON表示が残る | 設定時の確認と現在状態の保証を分離する表示へ修正 |
| private窓が残る状態で復元要求を送れる | 拡張側で送信直前の窓・許可状態を確認する回帰試験を追加 |
| ブラウザ異常終了で復元案内を失う | 変更可能性を送信前に保存する回帰試験を追加 |
| 未追跡ファイルやchecksumの上書きが配布に混入する | 配布対象を明示allowlistに固定し、ZIPとchecksumの既存拒否・排他新規作成を採用 |

調査・テスト・レビューの成功を実機の保護実証へ読み替えない。
実機検証は所有者の指示で省略しており、成功扱いにはしない。

開発時の上書き前バックアップはリポジトリ内の`backups/`、ビルド出力の退避は`build/backups/`に保持した。
これらとテストプロファイル・復旧マーカーはGitやZIPに含めない。
個人辞書・履歴の読取、既存設定の直接編集、実PCへのホスト登録、Public化は実行していない。
